# Réseau, zones, sauvegarde

- Room `narco`, `roomId` = code 4 lettres (sans I/O), privée, 3 joueurs distincts max (`onAuth`).
- Identité : `playerId` (UUID en `localStorage`) passé au join ; joueurs indexés par `playerId`. Déconnexion → `connected=false`, état gardé ; même `playerId` = réattachement.
- Reconnexion auto (backoff + `visibilitychange` / `pageshow` / `online`). Room vide conservée `config.room.emptyRoomTtlSeconds`. Code de la dernière room en `localStorage` (iOS tue les onglets).
- Proxy Vite `/colyseus` → `localhost:2567` : une seule origine, LAN et HTTPS sans config.
- **Zones** : `Player.zone` = `street` ou id d'intérieur ; une seule room ; le client ne rend que sa zone. Les messages `move` portent la zone (ignorés si périmés). Ne pas confondre avec les quartiers zone1/2/3 de `locations.json`.
- **Mouvement** : le client propose une position prédite, `validateMove` la valide/corrige. Collisions : une seule implémentation (`shared/src/collision.ts`), obstacles par zone via `zoneArea`.
- **Horloge** : `shared/src/clock.ts`, accélérable en debug, extrapolée par le client depuis `state.clock`.
- **Sauvegarde** : snapshot JSON toutes les `config.persistence.snapshotSeconds` et à l'arrêt, `server/.data/rooms.json` (`NARCO_DATA_DIR`). Parties recréées avec leur code, joueurs hors ligne jusqu'à reconnexion, temps figé pendant l'arrêt. `schemaVersion` par partie (voir `labo.md`). SQLite plus tard.
- Env : `NARCO_SERVER_PORT` (2567), `NARCO_SERVER_HOST` (0.0.0.0). Ne pas utiliser `PORT`.
- **Collisions** (`shared/collision.ts`, même fonction et mêmes paramètres pour la prédiction client et la validation serveur, `config.collision`) : sous-pas ≤ `maxSubStep` (≤ demi-rayon, pas de tunnel), résolution obstacles + bornes en quelques passes (`settle`, plus de renvoi dans un meuble collé au mur), éjection vers le point libre le plus proche (`ejectToFree`), repli par axes séparés quand un coin saillant est pris de face. Le serveur ne corrige qu'au-delà de `correctionThreshold`. Écarts : deux obstacles se touchent ou laissent `2 × rayon + passageMargin` (`findSlits`) ; vérifié au chargement (intérieurs, impasses générées) et au placement des meubles (avec la porte qui doit rester atteignable). Audit : `npm run collisions [tirages]` (version courte dans les tests).
- **Lissage / vibrations** (`shared/src/smoothing.ts`, `config.netSmoothing`) : tout lissage passe par `smoothFactor(raideur, dt)` (identique à 30 et 60 fps). Ordre des `useFrame` (`client/src/game/framePriority.ts`) : personnages (-2), caméra (-1, `updateMatrixWorld`), étiquettes DOM (0) — sinon caméra et étiquettes ont une frame de retard. Corrections : `Reconciler` mesure l'écart au `seq` envoyé (le chemin fait depuis est gardé), ignore sous `correctionIgnoreDistance`, fondu jusqu'à `correctionSnapDistance`, recalage au-delà. Joueurs distants : `SnapshotBuffer`, interpolés avec `remoteDelayMs` de retard. Collisions : un sous-pas qui recule (renfoncement entre deux coins proches) est refusé. Simulation complète dans `smoothing.test.ts`.
